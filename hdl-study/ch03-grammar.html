03 基本語法 — Verilog 的型別、運算子與八種 Block

資料型別、運算子、模組與實體、四種模型、八種 block、阻塞與非阻塞。原始投影片 38 張，估計閱讀 55 分鐘。

學習目標

  • 寫出 Verilog 的常數格式（8’haf、1’bz），並說明 ` 與 ’ 兩種引號的用途差別。
  • 分辨可合成與不可合成的運算子與敘述。
  • 說明模組 (module) 與實體 (instance) 的關係，並寫出埠對應的兩種寫法與參數傳遞。
  • 認出 Verilog 的四種模型：行為、RTL、閘級、開關級，並讀懂各自的範例程式。
  • 說出 Verilog 的八種 block 各自的性質（並行／序列／程序式）。
  • 準確區分連續指定、阻塞指定與非阻塞指定在模擬與合成上的差別。
  • 讀懂 case／casex／casez 的差異，並寫出正反器與計數器的標準寫法。

3.5 運算子

投影片 p.6–7

與 C 語言類似（p.6）

Unary:    assign a = ~b; // bitwise not
Binary:   assign a = b & c; // bitwise and
                     such as: +, -, *, /, |, ^, <<, >>, 
Ternary: assign d = c ? a : b; // if 1, d=a; else d=b

可合成的運算子

  • Most ALU and logic operation designs are developed in library.（大部分 ALU 與邏輯運算的設計都已在程式庫中。）
  • In RTL model, the designs are “assigned” according to data flow.（在 RTL 模型中，設計是依資料流「指定」出來的。）

不可合成的敘述與運算子

  • Statements dependent to time or times, e.g., initial, repeat（依賴時間或次數的敘述）
  • Switch-level（開關級）
  • Operators used in compiling/simulation only, e.g., ===
  • Operators with no design/method in current library, e.g., / % (in some tool)

3.7 埠與接線的對應、參數傳遞

投影片 p.9–10

埠是內部觀點，接線是外部觀點（p.9）

投影片用兩個欄位標題說明：Port (Pin) – Internal View（埠／接腳，模組內部看）與 Net (Wire) – External View（網線，模組外部看）。圖上 Instance1 of M1 的三條線標為 Wire1、Node2、Net3，並附註 They may have the same or different names.（名稱可以相同也可以不同。）

  module M1(Clk, A, B);
    input  Clk;
    inout  A;
    output B;
    :
    :    
  endmodule

埠對應有兩種寫法：

Port-Associated Mapping:
     e.g., M1 Instance1(.A(Node2), .Clk(Wire1), .B(Net3));
Ordered Mapping:
   e.g., M1 Instance2(Wire1, Node2, Net3);

名稱對應 (.A(Node2)) 不怕順序寫錯，埠一多就該用它；順序對應 (M1 Instance2(...)) 比較短，但必須和宣告順序完全一致，改埠順序就會錯得無聲無息。

參數埠的宣告與實體化：

Declaration:
     e.g., module M1 #(parameter N=16)(Port1, Port2);
Instantiation:
   e.g., M1 #(8) Instance1 (Net1, Net2);

參數傳遞的四種寫法（p.10）

ADD  #(4, 8)  U1  (X, Y, Sum);
ADD #(.M(4), .N(8)) U1(.A(X), .B(Y), .S(Sum));
module ADD(A, B, S);
    parameter M=2, N=3;
    input [M-1:0] A;
    input [N-1:0] B;
        :
endmodule
module ADD #(
    parameter M=2,
    parameter N=3) (
    input [M-1:0] A,
    input [N-1:0] B,
    output [N:0]  S);
        :
endmodule

投影片對預設值的註記照錄：default values should / cannot given for some compilers.（某些編譯器要求／不允許給預設值。）

3.9 Verilog 的四種模型

投影片 p.12

投影片由上而下分成四個橫帶，抽象層級由高到低：行為 → RTL → 閘級 → 開關級。四段程式都是同一件事的不同層級寫法。

1. 行為模型（Behavioral Model / Procedural Model）

module counter(Clk, Q);
    input  Clk;
    output [15:0] Q;
    reg    [15:0] Q;
    always@(posedge Clk)
	Q=Q+1;
endmodule

圖示為一個運算子梯形接到帶時脈記號的暫存器，輸出再回授到自己的輸入。

2. 暫存器轉移層（Register Transfer Level / Data-Flow / Register-Transfer Model）

module adder(A, B, Ci, Co, S);
    input [31:0] A, B;
    input Ci;
    output Co;
    output [31:0] S;
    assign {Co, S}=A+B+Ci;
endmodule

圖示為兩條暫存器橫條餵進一個標著 operator 的梯形，輸出再寫入下方第三條暫存器橫條 — 這正是「暫存器之間的資料轉移」。

3. 閘級模型（Gate Level Model / Structural Model）

module SR_latch(S, R, P, Q);
    input S, R;
    output P, Q;
    nor g1(Q, R, P);
    nor g2(P, S, Q);
endmodule

圖示為兩個交叉耦合的 NOR 閘。注意這裡用的是閘級原始元件 nor，並給了實體名 g1、g2。

4. 開關級模型（Switch Level Model）

module multiplexer(A, B, C, F);
    input A, B, C;
    output F;
    tranif1 (F, A, C);
    pmos    (F,B,C);
endmodule

圖示為一個 MOS 電晶體符號與一個傳輸閘（蝴蝶結）符號。

實務上只有第 1、2 種常用（對應第 01 章 p.16 的 Behavioral Mode 與 RTL Mode）。閘級通常是合成工具的輸出而不是人寫的輸入；開關級幾乎只在元件庫開發或特殊電路才會碰到。

3.10 閘級設計範例與突波消除

投影片 p.13

範例 1：正緣偵測器

module posedge_detector(in, out);
input in;
Output out;
not #5 (c, b), (b, a), (a, in);
nand #10 (out, in, a);
endmodule

原文 Output out; 的 O 是大寫，Verilog 區分大小寫，此處照抄不修正。

電路是三個反相器串成鏈 (in → a → b → c)，再把原輸入 in 與延遲後的 a 一起送進 NAND。#5 與 #10 是閘延遲。

範例 2：突波 (Hazard / Glitch) 消除

p.13 的 3 變數卡諾圖（照錄；列為 AB、欄為 C）
AB \ C01
0001
0101
1111
1000

投影片把 C=1 欄中 AB=01 與 AB=11 兩格圈紅 — 這是會產生突波的相鄰處。右側的時序圖顯示 A 上升時 F 出現一個窄脈衝。

修正方式是加入共識項 (consensus term)。投影片用動畫把第一行換成第二行：

assign F=(A&B)|(~A&C);
assign F=(A&B)|(~A&C)|B&C;

為什麼有效：當 B=C=1 時，不論 A 怎麼跳，B&C 這一項恆為 1，F 就被固定住，中間的空檔被填滿。這個多餘項在邏輯上完全不改變真值表，純粹是為了消除時序上的毛刺。

3.11 RTL 由程式庫合成

投影片 p.14–15

基本合成方法（p.14）

投影片列出三步：

  1. To parse an arithmetic-logic expression into a tree（把算術邏輯式剖析成一棵樹）
  2. Matching parameters and checking the port-net consistencies（比對參數並檢查埠與網線的一致性）
  3. Calling the instance from macro-block libraries and connecting.（從巨集區塊程式庫叫出實體並接線。）

範例式子是 E.g., assign A=B + ~C;，圖中畫出它的剖析樹：根是 =，子節點為 A 與 +；+ 的子節點是 B 與 ~；~ 的子節點是 C。

三個 RTL 設計範例（p.15）

module comparator(A, B, GT, EQ, LT);
parameter SIZE=16;
input [SIZE-1:0] A, B;
output GT, EQ, LT;
assign GT=(A>B);
assign EQ=(A==B);
assign LT=(A<B);
endmodule 
module decode3to8(in, out);
parameter SIZE=3;
input  [SIZE-1:0] in;
output [1<<SIZE-1] out;
assign out=1’b1<<in;
endmodule 
module multiplexer(F, C, A, B);
input  A, B, C;
output F;
assign F=C?A:B;
endmodule

三個範例都只用 assign，沒有任何 always — 這就是 RTL／資料流風格：描述「輸出等於輸入的什麼函數」，由合成器去挑程式庫裡的巨集區塊。

3.12 匯流排的切割與串接

投影片 p.16

圖上兩條 4 位元匯流排 A[3:0] 與 B[3:0] 由上方進入，合成 8 位元的 C[7:0]，再從下方切成 D[1:0] 與 E[5:0]。

assign A=C[7:4];
assign B=C[3:0];
assign D=C[7:6];
assign E=C[5:0];
assign C={A,B};
assign {D, E}=C;

重複 (replication) 的例子：

assign data = 2{4'b0001, 2{3‘b011}};

投影片下方用兩條綠色橫條展開結果：

0001-001-001-0001-001-001
00010010010001001001

這一頁有三處原文瑕疵，全部照原樣呈現：(1) 4'b0001 用直引號，3‘b011 卻用全形左引號；(2) 重複語法寫成 2{...}，合法的 Verilog 應為 {2{...}}；(3) 兩條展開字串長度互相矛盾（24 位 vs 20 位）。

正確寫法是 assign data = {2{4'b0001, {2{3'b011}}}};，展開後為 0001 011 011 0001 011 011 共 20 位元。投影片的 001 與位數都和 3'b011 不符，推測是手寫示意時的筆誤。

3.13 什麼是「行為」

投影片 p.17

這一頁只有一張卡通圖與兩個標籤：一個綠色小人舉著手，一道黃色閃電打在他的右手上標著 Event!，左上角一顆太陽照過來標著 Another Event!。

教學重點：「行為」就是對事件的反應。電路平時什麼都不做，事件（時脈邊緣、訊號變化）一來才反應 — 這正是 always@(事件) 的語意。

3.15 Verilog 的事件

投影片 p.21

3.16 電路時間與 CPU 時間、時間輪

投影片 p.22–23

兩種時間（p.22）

圖的中段是一支標著 Simulated Circuit Time（模擬的電路時間）的白色箭頭，下方是一排六個標著 Simulation CPU Time（模擬所花的 CPU 時間）的綠色箭頭。虛線把每個訊號邊緣對應到一個 CPU 時間格 — 說明兩種時間各自獨立前進。

  • Circuit Time >> CPU Time for Small Low-Speed Design（小型低速設計：電路時間遠大於 CPU 時間）
  • CPU Time >> Circuit Time for Large High-Speed Design（大型高速設計：CPU 時間遠大於電路時間）

換句話說：模擬一顆小晶片跑 1 秒的行為，電腦可能只花幾毫秒；但模擬一顆大型高速晶片跑 1 微秒，電腦可能要算好幾個小時。這是驗證工程的核心成本。

時間輪（p.23）

投影片的一句定義：Internal Queue Structure for Event-Driven Simulation （事件驅動模擬的內部佇列結構）。

圖是一個大的綠色圓形箭頭（輪子），輪緣上用黃線與藍色別針掛著十個白色行李標籤，每個標籤都寫著同樣的三行字：

Event
Circuit time
Cause & Effect

事件驅動模擬器的運作方式：每個待處理事件都帶著「發生時間」與「因果關係」掛在時間輪上，模擬器按電路時間順序一個一個取下來處理，處理時又可能產生新的事件掛回輪子。這就是為什麼模擬時間不是等速前進 — 沒有事件的時段會被直接跳過。

3.17 左值與 reg

投影片 p.24

  • Left Value（左值）：The variable left to the assignment of an expression in C or Verilog（在 C 或 Verilog 中，位於指定運算左邊的變數）。
  • Register（暫存器）：
    • Register circuit usually denotes the flipflop array, such as counters.（暫存器電路通常指正反器陣列，例如計數器。）
    • reg in behavioral mode may not necessarily be a register（行為模式中的 reg 未必真的是暫存器。）
    • reg keeps the variable data while elapsing in simulation phase（reg 在模擬過程中保存變數的值。）
    • Declare reg for all left values in behavioral model blocks.（行為模型區塊中所有的左值都要宣告為 reg。）
    • reg can also define memory arrays during simulation phase.（reg 也可以在模擬階段定義記憶體陣列。）

			:

3.21 三種指定敘述

投影片 p.29

這是全章最關鍵的一頁。Verilog 有三種指定，語意完全不同。

Assignments（照錄 p.29）
種類模擬時 (Simulation)合成時 (Synthesis)
Continuous Assignments
連續指定 =（用於 assign）		 Evaluate RHS and change Lvalue at 1 step when any event occurs.
（任何事件發生時，一步內算完右式並改變左值。）		 Draw a wire from the RHS to the Lvalue.
（從右式拉一條線到左值。）
Blocking Assignments
阻塞指定 =（用於程序式區塊）		 “Blocking” means to be locked at the dependency.
Evaluate RHS and change Lvalue at 1 step when any event occurs.
（「阻塞」是指被相依性鎖住；事件發生時一步內算完並改變左值。）		 Cannot be synthesized if any data dependency.
（只要有資料相依性就無法合成。）
Non-blocking Assignments
非阻塞指定 <=		 Evaluate RHS at the first phase then change Lvalue at the second phase.
（第一階段先算右式，第二階段才改變左值。）		 Cannot be synthesized if any data dependency; There won’t be dependency if all are non-blocking.
（有相依性則無法合成；但若全部都用非阻塞，就不會有相依性。）

最後那句是整頁的結論：只要同一個 always 區塊裡全部使用非阻塞指定 <=，就不會產生資料相依性問題，因此可以合成。這也是「循序邏輯一律用 <=、組合邏輯一律用 =」這條業界慣例的由來。

3.23 阻塞與非阻塞的逐步比較

投影片 p.32–33

投影片用四段程式做對照，初始值都假設 X==3 且 Y==6。

阻塞指定（左欄）

always@(posedge Clk) 
	begin
		X = Y + 1;
		Y = X << 1;
	end

投影片的說明照錄：Assume X==3 and Y==6 at first, the simulator evaluates Y+1==7 and gives 7 to X; then it evaluates X<<1 == 14 and gives 14 to Y.

也就是 X=7、Y=14。第二行用到的是剛被改過的 X。

always@(posedge Clk) 
	begin
		Y = X << 1;			X = Y + 1;
	end

投影片的說明照錄：Assume X==3 and Y==6 at first, the simulator evaluates X<<1==6 and gives 6 to Y; then it evaluates Y+1 == 7 and gives 7 to Y.

原文最後寫「gives 7 to Y」，但該行程式指定的是 X。依程式應為 Y=6、X=7。照原文保留，不修改投影片文字。

重點：阻塞指定的結果會隨著兩行的先後順序而改變（①得到 X=7,Y=14；②得到 Y=6,X=7）。

非阻塞指定（右欄）

always@(posedge Clk) 
	begin
		X <= Y + 1;
		Y <= X << 1;
	end

投影片的說明照錄：Assume X==3 and Y==6 at first, the simulator evaluates X’==Y+1==7 and Y’==X<<1==6, then it gives values: X←X’==7 and Y←Y’==6;

也就是 X=7、Y=6。兩個右式都用舊值計算。

always@(posedge Clk) 
	begin
		Y <= X << 1;		X <= Y + 1;
	end

投影片的說明照錄：The simulation results will be the same as the above and it can be synthesized.（結果與上面相同，而且可以合成。）

重點：非阻塞指定的結果與書寫順序無關，因此可以合成。這正是 §3.21 最後那句結論的具體示範。

電路觀點（p.33）

p.33 用電路圖解釋為什麼。兩半各畫兩個虛線框的正反器 F1（上）與 F2（下），每個虛線框內有兩個綠色閂鎖器：第一個標 D、輸出 Q’，第二個標 Q，並註明 Dual latches（雙閂鎖器）與 FF。粉紅色線把兩個正反器的輸出交叉接到對方的輸入。

begin
  F1=F2;
  F2=F1;
end
begin
  F1<=F2;
  F2<=F1;
end

右半邊的圖在每個 Q 輸出端多畫了一個粉紅接點才交叉過去 — 這就是關鍵：非阻塞指定取的是交換前的舊值，所以 F1 與 F2 真的會互換；左邊的阻塞寫法則是 F1 先變成 F2，第二行再把這個新的 F1 寫回 F2，結果兩者都變成原本的 F2，交換失敗。

重點整理

  1. 常數格式是「位寬 + ' + 基底 + 數值」，如 8’haf；` 反引號用於編譯指令，' 單引號用於常數位寬，兩者不同鍵。
  2. 不可合成的東西有跡可循：依賴時間或次數的（initial、repeat）、開關級、只在編譯／模擬用的運算子（===），以及程式庫裡沒有對應設計的（/、%）。
  3. 模組是樣板，實體才佔資源；埠對應有名稱對應與順序對應兩種寫法，埠一多就該用名稱對應。
  4. Verilog 有四種模型：行為 → RTL → 閘級 → 開關級。實務只常用前兩種，閘級通常是合成工具的輸出。
  5. 加入共識項可以消除突波：(A&B)|(~A&C) 加上 B&C 後，邏輯不變但毛刺消失。
  6. 行為就是對事件的反應；always@(...) 括號裡的就是敏感度列表，可用 posedge、negedge 與 or 組合。
  7. 電路時間與 CPU 時間是兩條獨立時間軸；事件驅動模擬靠「時間輪」這個佇列把事件按電路時間排程。
  8. reg 不等於硬體暫存器，它只是「可在程序式區塊中被指定的變數型別」；但行為區塊裡所有左值都必須宣告為 reg。
  9. 三種指定要分清楚：assign 的連續指定等於拉一條線；阻塞 = 會立刻生效、順序會影響結果、有相依性就不能合成；非阻塞 <= 先全部算完再一起寫入，與順序無關，全部用非阻塞就不會有相依性。
  10. 交換兩個值必須用非阻塞：F1=F2; F2=F1; 會讓兩者都變成舊的 F2；F1<=F2; F2<=F1; 才真的互換。
  11. casex 比 casez 寬鬆：casez 只把 z／? 當不比對，casex 連 x 也不比對。
  12. 同步與非同步重置的差別只在敏感度列表：非同步把 posedge Rst 也列進去。
